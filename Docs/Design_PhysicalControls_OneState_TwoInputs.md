# Органы управления: два глагола, одно состояние (монитор + VR)

> **Дата:** 2026-08-20 · **Ревизия 3** (ревизия 2 = два глагола; здесь: VR не открывает камеру DIVE, а подтягивает **граф действий**; world-меню на хите; три пояса ACTS / панель / GRIP).
> **Статус:** дизайн-решение для яруса 2 и standing-VR (см. аудит DIVE 2026-08-19 §10.8). Ярус 1 (кинематические continuous-действия в Interact) не отменяется. Код яруса 2 / action host **не** начинать без триггера.
> **Затрагивает:** слой устройств (control-компоненты), GRIP (хват тел), DIVE (сессия **и** граф действий), DIVEGRIPBridge, хост IMC / будущий VR-интерактор.
> **Related:** [`Additional/DeviceInteractionModel.md`](Additional/DeviceInteractionModel.md), [`Plugin_Architecture_Principles.md`](../../../Docs/Plugin_Architecture_Principles.md).

---

## 1. Ядро решения: два разных глагола

Взаимодействие с устройством — это **два разных намерения**, и они не должны делить один вход или один механизм:

| Глагол | Что | Механизм | VR-ввод | Монитор-ввод |
|--------|-----|----------|---------|--------------|
| **Взять** (grab) | Свободные / съёмные тела: снятая крышка, сорванная гайка, инструмент, MESS-модуль | GRIP: PD-силы на grabbable-теле | **Боковая кнопка** (grip) | Physical-режим LMB → мост (cursor-pull) — уже работает |
| **Воздействовать** (interact) | Панельные органы: крутилка, тумблер, слайдер, кнопка | Детерминированный жест → значение на control-компоненте; меш следует значению | **Курок** (hold = continuous primary, click = discrete primary); **кнопка меню** = остальные действия на хите (§10) | Interact LMB / меню — **ярус 1 уже так работает**; в ярусе 2 тот же жест форвардится в компонент |

Конфликт «хотел крутилку — схватил устройство» и «потянул крутилку — улетело устройство» снимается **структурно**, а не тюнингом:

- у органов управления **нет** grabbable-маркера → grip-кнопка их не видит;
- у корпуса **нет** interactable-регистрации → курок его не видит;
- interact-жест кинематический → **нулевые силы реакции** на корпус, физичность устройства не мешает.

## 2. Почему физ-хват не годится как магистраль для панельных контролов

(Аргументы, похоронившие ревизию 1.)

1. **Реакция через констрейнт.** Тяга за констрейнт-ограниченную крутилку передаёт силы на корпус. Свободностоящее физичное устройство ползёт или улетает. Якорить всё нельзя — MESS-модули по замыслу съёмные и физичные.
2. **Точность.** PD-силы на маленьком рычаге = джиттер; чёткие детенты недостижимы; тренажёрные оценки («выставь ровно 3-ю позицию») требуют детерминизма.
3. **Пик в VR.** Толстый trace руки против 2-сантиметровой ручки на плотной панели — постоянные промахи в корпус.
4. **UX-конвенция VR.** Grip = держать предмет, курок = использовать — стандарт индустрии; смешивание глаголов на одной кнопке дезориентирует.

## 3. Архитектура

```text
            ┌──────────────────────────────────────────────────┐
            │  Устройство (префаб; слой вне DIVE и вне GRIP)   │
            │  ControlComponent — ЕДИНСТВЕННЫЙ владелец:       │
            │    значение, лимиты, детенты, события, звук, MESS│
            │    меш следует значению (кинематика; opt-in      │
            │    constraint-drive — §5)                        │
            │  API: Begin / ApplyAngleDelta / End / GetNormalized│
            └────────▲──────────────────────────▲──────────────┘
   interact-глагол   │                          │   interact-глагол
        ┌────────────┴───────────┐   ┌──────────┴─────────────────┐
        │ Монитор (DIVE presentation):│   │ VR standing (host action host): │
        │ сессия → Catalog / Bindings │   │ курок = primary; кнопка меню =  │
        │ + IDIVEProxyDrive (ярус 2)  │   │ world-меню того же графа;       │
        │                             │   │ камера сессии НЕ включается     │
        └────────────────────────┘   └────────────────────────────┘

   grab-глагол (отдельно): GRIP — grip-кнопка в VR / Physical LMB через мост
   на мониторе — только grabbable-тела (съёмные части, инструменты, модули).
```

Роли по слоям:

| Слой | Владеет | НЕ владеет |
|------|---------|------------|
| **Устройство** | Значение, лимиты, детенты, события, звук, MESS; регистрация «мои примитивы» | Вводом |
| **GRIP** | Прицел руки, хват, PD-силы — **только тела** | Контролами |
| **DIVE** | Граф действий (Catalog / Bindings, primary, `GetDisplayState`); мониторная **презентация** (камера, chrome, режимы) | Физикой, VR-вводом, состоянием контрола; world-space меню |
| **Host / DeviceControlKit** | VR-интерактор (курок + кнопка меню), IMC, world-виджет меню, префабы | Каталогом действий (он на устройстве / в DIVE) |

Ключевые следствия:

- **Монитор уже готов.** Ярус 1 (Rotary/Threaded в Interact) — это и есть interact-глагол. Миграция на ярус 2: тот же биндинг, действие вместо записи в transform форвардит дельту в компонент (через `IDIVEProxyDrive` / registry — контракт V1–V4 доращен заранее). Авторинг каталога не меняется.
- **`IDIVEProxyDrive` = мониторный адаптер interact-глагола.** Не «опциональная кинематика», как в ревизии 1, а штатный вход яруса 2 со стороны DIVE. **Код сегодня** всё ещё стартует этот путь с Physical primary (`TryBeginProxyDriveAtScreenPosition`) — хвост ревизии 1; перенос на Interact — работа яруса 2.
- **VR-интерактор — не GRIP и не камера DIVE.** Host-компонент: резолв хита на inspectable, primary с курка, world-меню с отдельной кнопки, маппинг дельты позы руки на ось (брат `MapScreenDeltaToAxisAngle`). Исполнение идёт через **граф действий DIVE** (тот же Catalog / Bindings), не через новый VR-каталог. GRIP остаётся чистым grab-движком. Камера сессии во standing-VR **не** включается (§8–§10).
- **Кнопки** — дискретный случай того же глагола: клик курка / клик LMB / строка меню → `Execute` → компонент.

## 4. Сквозной сценарий: гайка (проверка модели)

1. **Interact:** курок/LMB-жест крутит резьбу (ярус 1 Threaded или компонент) → HUD «2.5 / 4 об.» → на пороге detach + `SetSimulatePhysics` + **появляется grabbable-маркер**.
2. **Grab:** гайка теперь тело — grip-кнопка / Physical LMB снимает её и откладывает (мост и рука уже это умеют).

Два глагола сменяют друг друга ровно в момент, когда контрол становится телом. Ни одного конфликта ввода.

## 5. Где физ-хват контрола всё же уместен (opt-in, не дефолт)

- Крупные органы, где физичность — фича: штурвал вентиля (двуручный), тяжёлая дверца с инерцией, рубильник с ходом.
- Условия: устройство **заякорено** (kinematic корпус — реакция никуда не уходит), движущаяся часть симулирует в пределах констрейнта, на ней grabbable-маркер.
- Это осознанный выбор per-control. Компонент при этом всё равно владеет значением (читает позу констрейнта) — семантика едина с interact-контролами.

## 6. Факт (из ревизии 1): GRIP вход-агностичен

Мост требует от цели только `IsSimulatingPhysics()` + `CanGripPrimitive` (`DIVEGRIPPhysicalDriveProvider.cpp:195-204`); `TryGrabFromHit` отклоняет лишь несимулирующие тела (`GRIPHandComponent.cpp:1461-1464`). Констрейнт-ограниченное тело хватается с монитора уже сегодня. Это питает §5 (opt-in крупные органы) и grab-глагол для тел — но не делает физ-хват дефолтом для панельных контролов (§2).

## 7. Ввод хоста: три жеста панели + ACTS отдельно

GRIP уже отдаёт **только** хват (`IA_Grab` → `HandleGrabPressed`). ACTS уже отдаёт **только** мировой interact (`IA_Interact` → press / hold-to-complete для пунктов **своего** меню). Непрерывная крутилка — **не** ACTS Hold и **не** GRIP Grab.

На VR-контроллере (хост IMC, не плагины):

| Жест | IA (имена хоста) | Куда | Что в прицеле |
|------|------------------|------|----------------|
| Боковая (grip) | `IA_Grab` | GRIP Rig | Только `IGRIPGrabbable` / симулирующие тела |
| Курок hold | `IA_DeviceControl` | action host / VR-интерактор | Primary **continuous** на хите inspectable (крутилка) |
| Курок click | тот же | тот же | Primary **discrete** (кнопка, тумблер) |
| Отдельная кнопка меню | `IA_DeviceMenu` | тот же, world-виджет | Остальные видимые действия на **этом** меше (§10) |
| ACTS interact | `IA_Interact` | ACTS Player | Мировой пояс: шкаф с 2 м, «Детальный осмотр» |

Курок **не** вешать на `IA_Interact` ACTS и **не** открывать им меню панели: иначе click по кнопке, крутилка и «ещё действия» неразличимы. На мониторе это уже LMB vs RMB; во VR та же пара plus grip.

На мониторе два глагола разделены **режимом сессии**, не кнопками: Interact LMB = воздействовать (ярус 1 сегодня), Physical LMB = grab через мост. Во standing-VR режимы сессии **не нужны**.

Пик мелких ручек: **touch-volume** (capsule на пальце / небольшой overlap), не толстый line trace в корпус. Trace руки GRIP остаётся для grab.

## 8. Три пояса (не два меню в одном)

| Пояс | Когда | Кто | Пример |
|------|--------|-----|--------|
| **Мир** | ещё не у панели | ACTS | «Детальный осмотр», открыть шкаф с 2 м |
| **Панель** | луч / палец на pickable меше `UDIVEInspectableComponent` | граф действий DIVE | крутилка, «снять модуль», admin |
| **Хват** | grabbable тело | GRIP | сорванная гайка, крышка |

Каталог DIVE **не** вливать в ACTS world menu (два плагина, два пояса). Хост кладёт два виджета на **разные** кнопки.

Опционально: пункт ACTS «точный осмотр» может открыть **полную** DIVE-сессию (камера) — сесть за стол. Это не standing-VR у панели и не автостарт по лучу.

## 9. Бесшовное «подтягивание» DIVE: граф действий, не камера

DIVE склеен из двух слоёв. Во VR у панели нужен только первый.

| Слой | Что | Standing-VR у панели | Монитор |
|------|-----|----------------------|---------|
| **Граф действий** | Bindings + Catalog, `PrimaryActionIndex`, `GetDisplayState`, `Execute` / `BeginInteraction` | да | да |
| **Презентация** | камера, orbit/zoom, chrome, Interact/Physical, Focus/Isolate как «подъехать» | **нет** | да |

Луч контроллера по устройству **не** вызывает `RequestSession()` и **не** крадёт HMD.

Бесшовный момент — **action host без презентации** (host / DeviceControlKit, не новый VR-каталог):

1. Луч или touch-volume попал в pickable примитив inspectable (те же pick-правила, что в сессии: видимый меш / shape, `DIVE.PickProxy`, exclusions).
2. Подсветка — тот же hover overlay, что в Interact-режиме сессии (affordance «здесь есть interact»).
3. Если есть primary — курок готов его исполнить.
4. Кнопка меню собирает строки **этого** хита, не всего устройства.
5. Луч ушёл / отошёл: закрыть меню; **не** рвать непрерывный жест, пока курок зажат.

Порядок постройки, когда дойдёте до VR: сначала headless-слот Begin/Update/End без камеры, потом world-меню. Меню без слота крутилку не закроет.

### Факт кода сегодня (шов, не баг продукта)

- Query строк: `UDIVEInspectableComponent::AppendConfiguredContextMenuEntries` и `TryResolvePrimaryAction` **сессии не требуют**.
- `UDIVESessionSubsystem::BuildContextMenuEntries`, `TryBeginContinuousAction`, Focus/Isolate, chrome — требуют `IsSessionActive()`.
- Значит standing-VR нельзя «просто вызвать сессию»; нужен action host, который владеет continuous-слотом без презентации. Не делать это, пока нет триггера яруса 2 / VR.

## 10. Контекстное меню во VR

**Нужно.** `PrimaryActionIndex` закрывает один очевидный жест. На одном меше легитимно висят ещё admin, «прочитать шильдик», «демонтировать», Focus/Isolate. Без меню их некуда деть, кроме как размазать по кнопкам контроллера.

Это **не** 2D Slate-меню сессии и **не** ACTS world menu. Хост рисует world-space панель у точки хита (или у off-hand); выбор лучом, подтверждение курком. DIVE отдаёт уже собранный список строк.

### Фильтр строк (не as-is)

`GetDisplayState` остаётся (Condition прячет, `CanExecute` серит). Плюс доступность действия:

| Значение (чертёж; в коде ещё нет) | Монитор-сессия | Standing-VR |
|-----------------------------------|----------------|-------------|
| `Session` | показывать | скрыть |
| `World` | скрыть | показывать |
| `Both` (дефолт для каталожных операций) | показывать | показывать |

Практическая таблица для built-in:

| Действие | Сессия | VR у панели |
|----------|--------|-------------|
| Rotary / Threaded / кнопка (primary) | LMB / меню | курок; в меню можно не дублировать, если это единственный primary |
| Каталожные операции на детали | меню | world-меню |
| Focus / Isolate | меню (камера) | **скрыть** (`Session`) — это про камеру DIVE, не про стоять в комнате |
| Admin Simulate / Delete | меню | можно `Both` (инструктор); Shipping по-прежнему прячет Admin |

Isolate во VR не должен прятать соседние шкафы уровня тем же кодом, что Isolate сессии.

Если на меше **ровно одно** видимое World/Both-действие и оно primary — меню можно не открывать, курок делает его сразу. Меню нужно, когда видимых строк > 1 или primary нет, а каталог есть.

## 11. Открытые пункты (решать при постройке первого контрола / VR)

1. **Дом action host / VR-интерактора:** host game module или `DeviceControlKit`; touch-volume vs переиспользование aim.
2. **Маппинг дельты руки на ось** — хелпер уровня компонент-кита (брат `MapScreenDeltaToAxisAngle`).
3. **Headless continuous-слот** — вынести владение Begin/Update/End из «только активная камера-сессия» (сегодня `TryBeginContinuousAction` требует `IsSessionActive()`).
4. **`Session | World | Both` на действии** — или эквивалент, чтобы Focus не всплывал у панели.
5. **HUD при VR-жесте:** событие компонента / `NotifyValueChanged` → host UI; DIVE-HUD сессии остаётся мониторным.
6. **Haptics на детентах** (VR) — событие компонента → контроллер.
7. Раскладка `IA_DeviceMenu` на конкретную кнопку контроллера — хост.

## 12. Что НЕ делать

- Физ-хват как дефолт панельных контролов (§2).
- Один жест на «взять», «воздействовать» и «меню».
- `RequestSession()` / кража HMD, когда луч попал в устройство (§9).
- Вливать каталог DIVE в ACTS world menu (§8).
- VR-интерактор внутри GRIP; world-меню внутри DIVERuntime (Slate сессии).
- Отдельный ассет-слой контролов в сессии (отвергнуто аудитами).
- Контролы внутри DIVERuntime; второй физический риг в DIVE.
- Не начинать ярус 2 / action host без триггера (VR-паритет / контролы вне DIVE / MESS-телеметрия).
